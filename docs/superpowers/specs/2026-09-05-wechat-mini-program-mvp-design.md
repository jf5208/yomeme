# 宠物 Meme 微信小程序 MVP 设计

## 目标

把现有宠物 Meme 网页的核心体验迁移为原生微信小程序，让用户在微信里更容易试用、保存和分享：上传一张单动物 Meme 模板与 1 到 3 张自家宠物照片，尽量只替换动物主体，保留模板的文字、构图、动作、神态和网图质感。

第一版验证两件事：

1. 三次免费体验能否让新用户理解产品价值并成功生成满意图片。
2. 用户体验后是否愿意通过人工购买兑换码继续使用。

## 产品范围

第一版包含：

- 微信静默身份识别，新用户自动获得 300 积分。
- Seedream 单模型生成，每次成功生成消耗 100 积分。
- 一次首次生成和一次输入调整意见后的再次生成；再次生成同样消耗 100 积分。
- 一张 1:1 单动物 Meme 模板和 1 到 3 张同一只宠物照片。
- 上传前展示两张原创推荐构图参考图。
- 生成结果预览、保存到相册和主动分享。
- 兑换码充值，以及仅管理员可使用的兑换码创建入口。
- 简短、手机可读的使用说明。

第一版不包含：

- 微信支付或其他在线支付。
- 用户自行填写 API Key。
- Gemini 或用户可见的模型选择。
- 社区、公开作品广场、模板素材库。
- 多动物模板、复杂局部编辑、历史作品管理。
- 自动去除来源不明图片的水印。

现有网页与扣子部署保持不变，小程序作为独立目录开发，不覆盖现有版本。

## 用户流程

### 首次进入

1. 小程序使用微信身份静默识别用户，不要求注册账号或填写手机号。
2. 数据库中没有该用户时，创建用户记录并发放 300 体验积分。
3. 首页顶部显示当前积分，但不暴露 Seedream、模型名称或 API 信息。

### 创建 Meme

1. 用户先看到“选这种模板，生成效果更稳定”的推荐构图区。
2. 推荐区展示两张原创示意图：单只动物正脸大头；单只动物半身且表情明显。
3. 推荐区只作示意，不能点击套用或下载。说明文案为“正方形、单只动物、主体清楚、背景简单”。
4. 用户选择一张 Meme 模板。选择前明确提示“仅支持 1:1 正方形模板”。
5. 客户端读取图片宽高。不是 1:1 时立即拒绝，并提示“请先裁成 1:1，本次不扣积分”。
6. 用户上传 1 到 3 张同一只宠物的照片，至少推荐一张清晰正脸。
7. 用户勾选素材权利确认后，生成按钮才可用。
8. 点击生成后先预占 100 积分，随后上传素材并发起生成。

### 结果与调整

1. 生成成功后确认扣除 100 积分并进入结果页。
2. 结果页支持保存到相册、分享给微信好友，以及返回重新创作。
3. 用户可以填写一次具体调整意见后再次生成；再次生成预占并消耗 100 积分。
4. 分享由用户主动触发，分享卡片可使用本次结果作为封面，并打开该结果的只读页面。

### 积分充值

1. 积分页显示当前积分与“兑换充值码”入口。
2. 用户在线下向运营者付款后获得兑换码。
3. 每个兑换码只能成功兑换一次，兑换后积分进入当前微信账号。
4. 第一批销售码默认充值 1000 积分，即 10 次 Seedream 生成；后台仍允许管理员设置其他积分数，便于测试或补偿。

## 页面设计

### 创作页

- 顶部显示产品名、当前积分和积分入口。
- 推荐构图区保持轻量，只展示两张小图和一行说明，不做轮播和模板库。
- 模板上传区在选择前明确显示正方形限制。
- 宠物照片区支持 1 到 3 张缩略图，并允许删除重选。
- 调整意见第一次可留空；生成过一次后显示具体示例。
- 主按钮使用暖珊瑚色，文案为“生成我家版本”。

### 结果页

- 生成图片作为页面主体，不放进多层卡片。
- 主要操作为保存、分享、按意见再生成。
- 明确显示再次生成会消耗 100 积分。

### 积分页

- 显示积分余额、兑换码输入框和兑换记录。
- 不展示模型成本、API Key 或后台服务名称。
- 暂不提供在线购买按钮；运营者可在客服说明中告知人工购买方式。

### 使用说明页

- 说明推荐模板、宠物照片选择、有效调整意见和积分规则。
- 使用亲切、简短的表达，不展示技术细节。

### 管理员入口

- 使用隐藏入口，仅配置的管理员微信身份可以访问。
- 支持批量创建兑换码、设置积分、复制新码、查看是否已兑换和停用未使用码。
- 非管理员即使知道页面路径也无法读取或修改兑换码数据。

## 视觉方向

- 轻可爱、清爽、不幼稚，面向偏女性的传播内容，但不把产品写成女性专属。
- 使用暖白背景、珊瑚粉主按钮和少量奶油黄点缀，不使用绿色主按钮。
- 爱心或爪印只作少量辅助装饰，不使用大面积渐变或装饰卡片堆叠。
- 所有关键操作以手机单手使用为优先，按钮与文字不得拥挤或重叠。

## 推荐构图素材与版权

- 两张推荐图必须为运营者自有照片、已取得明确商业授权的图片，或依据所用服务商业条款生成的原创示意图。
- 不使用小红书、抖音、微信表情、影视动漫、明星、知名角色或带平台水印的图片作为默认参考图。
- 推荐图只表达“单只动物、主体大小、角度和背景复杂度”，不复刻具体热门 Meme 的文字和画面。
- 保留推荐图来源、授权文件或生成记录，方便日后核查。

## 技术架构

### 小程序端

使用原生微信小程序实现，新增独立 `miniprogram` 目录。小程序负责：

- 页面展示和微信身份入口。
- 图片选择、缩略图预览与 1:1 比例校验。
- 上传进度、生成状态和中文错误提示。
- 保存到相册、主动分享与兑换码提交。

客户端不包含 Seedream API Key、管理员凭证或可直接修改积分的数据。

### 腾讯云开发

使用腾讯云开发提供：

- 云函数：登录初始化、创建生成任务、完成或退款、兑换积分、管理员创建兑换码。
- 云数据库：用户、生成任务、兑换码和兑换记录。
- 云存储：临时上传图片与生成结果。

云函数从微信调用上下文取得用户的 OpenID，不能接受客户端自行传入的用户身份。Seedream API Key 只配置在服务端环境变量中。

### Seedream 调用

生成云函数负责：

1. 校验用户、积分、模板比例、文件数量和权利确认。
2. 原子预占 100 积分并创建生成任务。
3. 读取云存储图片，沿用现有主体替换提示词调用 Seedream。
4. 下载有效结果并保存到云存储。
5. 成功时确认扣费并记录结果；失败时原子退回 100 积分。

前端只显示“正在生成”和面向用户的错误说明，不显示模型名、请求地址或服务端异常详情。

## 数据结构

### `users`

- `_openid`
- `credits`
- `trial_granted`
- `created_at`
- `updated_at`

### `generation_jobs`

- `job_id`
- `_openid`
- `status`: `reserved`、`succeeded` 或 `failed`
- `credit_cost`
- `template_file_id`
- `pet_file_ids`
- `result_file_id`
- `adjustment`
- `is_regeneration`
- `error_code`
- `created_at`
- `completed_at`

### `redemption_codes`

- `code_hash`
- `code_hint`
- `credits`
- `status`: `unused`、`redeemed` 或 `disabled`
- `redeemed_by`
- `redeemed_at`
- `created_by`
- `created_at`

数据库不保存兑换码明文。新码只在创建成功时向管理员显示一次。

### `credit_events`

- `_openid`
- `event_type`: `trial`、`generation_reserve`、`generation_success`、`generation_refund` 或 `redeem`
- `credit_delta`
- `balance_after`
- `job_id` 或兑换码记录标识
- `created_at`

积分余额和积分流水必须在同一事务中更新。每次操作使用唯一标识，避免重复点击、网络重试或云函数重试造成重复扣费或重复充值。

## 安全与隐私

- 所有积分和管理员权限由云函数验证，客户端展示值不能作为扣费依据。
- 上传前要求用户确认图片为本人创作、本人拍摄或已获授权。
- 不自动公开用户上传照片和生成结果；只有用户主动分享后才产生对外访问。
- 分享结果使用不可猜测的任务标识，只提供只读访问，不暴露原始宠物照片。
- 上传原图设置自动清理周期；生成结果在第一版保留有限时间，并在界面中明确提醒及时保存。
- 日志不记录 API Key、兑换码明文或用户图片内容。
- GitHub 仓库不得提交 `.env`、`.state`、数据库、虚拟环境、用户上传图或包含真实兑换码的截图。

## 异常处理

- 积分不足时不上传图片、不调用模型，直接进入积分页提示兑换。
- 模板不是 1:1、宠物照片数量不合规或未确认素材权利时，不预占积分。
- 图片上传失败或 Seedream 返回失败时，退回本次预占积分并显示“生成失败，本次未扣积分”。
- 任务处理中关闭小程序不影响最终结算；再次打开时可按任务状态恢复结果或退款提示。
- 长时间停留在 `reserved` 的任务由定时任务核查，确认没有成功结果后退款。
- 兑换码无效、已兑换或停用时不改变余额，并分别给出清楚提示。

## 验收标准

- 新微信用户首次进入只获得一次 300 积分。
- 非 1:1 模板在选择后立即被拒绝，且不扣积分。
- 1 张模板和 1 到 3 张宠物图可以完成一次 Seedream 生成。
- 成功生成扣除 100 积分；失败自动退回 100 积分。
- 调整再生成再次扣除 100 积分，并在操作前明确告知。
- 同一生成请求重复提交不会重复扣费。
- 1000 积分兑换码只能被一个微信账号兑换一次。
- 用户界面不出现 Seedream、Gemini、API Key 或模型选择。
- 非管理员无法创建、查看或停用兑换码。
- 两张推荐构图示意图在常见手机尺寸上清楚可见，不挤压上传流程。
- 用户可保存结果到相册并主动分享结果卡片。
- 现有网页和扣子部署不因小程序目录新增而改变。

## 实施顺序

1. 整理可公开的代码底座，移除仓库中不应跟随代码发布的运行数据与截图。
2. 建立原生小程序页面和云开发环境骨架。
3. 实现微信身份、300 体验积分和积分流水。
4. 实现图片选择、1:1 校验、推荐构图和上传流程。
5. 接入 Seedream 生成任务、预占扣费与失败退款。
6. 实现结果保存、分享和一次调整再生成。
7. 实现兑换码充值和管理员创建入口。
8. 完成真机、并发扣费、失败退款和权限验证。
